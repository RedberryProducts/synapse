# v0.3.1 — Reliable recording on Laravel Octane

Synapse 0.3.1 fixes conversation recording in Octane workers and makes the dashboard's streaming indicator match the server's behavior. This is a patch release: existing agent behavior, history, attachments, and approval checkpoints are preserved.

## Inspect agents on Octane

Tool executions now stay connected to the active request when running under Octane. Successful tool results, model-step details, and approval continuations are saved correctly instead of failing because the recorder missed the invocation.

Use the playground alongside your application's normal Octane server without adding Synapse-specific listeners, service-provider bindings, or worker warm/flush settings.

## See live updates on FrankenPHP and Swoole

Octane with FrankenPHP or Swoole delivers incremental responses. The dashboard now recognizes Swoole's streaming support and no longer shows an incorrect buffering warning.

Octane with RoadRunner completes and saves conversations, including approval decisions, but still delivers each response at completion. Its buffering notice remains; live streaming on RoadRunner is not part of this release.

Runtime guidance now records tested configurations and includes repeatable checks for streaming, history, partial failures, and approvals. Artisan serve, nginx/PHP-FPM, Sail, and classic FrankenPHP continue to support incremental responses.

## Upgrade from 0.3.0

```bash
composer require --dev 'redberry/synapse:^0.3.1'
```

For an existing Octane application, reload workers using the engine you run:

```bash
php artisan octane:reload --server=frankenphp
# Or: php artisan octane:reload --server=swoole
# Or: php artisan octane:reload --server=roadrunner
```

No new migrations, history reset, asset publication, or host-app npm build are required. PHP, Laravel, Laravel AI, and optional MCP requirements are unchanged.

For earlier versions, follow the [upgrade guide](https://github.com/RedberryProducts/synapse/blob/main/UPGRADE.md). The additive migrations from 0.2.0 and the separate legacy 0.1.x migration still apply when upgrading from those versions.
