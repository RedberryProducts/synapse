# v0.1.3 — Safer dev-only installs and clearer chat feedback

Synapse now handles development-only installations more safely in production and shows immediate feedback when an agent request starts.

## What changed

- **Safer production deployments:** the installer registers the published application provider only in `local`, behind a package-existence check. It migrates legacy bootstrap registration, preserves app edits on repeat installs, and stops with an actionable error when an existing registration cannot be verified as safe.
- **Self-contained published files:** new migrations and the published provider remain loadable after `composer install --no-dev` removes Synapse.
- **Immediate chat feedback:** an assistant-side `Loading...` indicator appears before the first stream event. Later tool, notice, or error events preserve reasoning already received.
- **Long agent names:** discovery cards and sidebar labels truncate cleanly and show the full name on hover.
- **Verified frontend bundle:** includes React Router 7.18.2, pinned for release builds after a newer patch failed a navigation regression test.

## Upgrade from v0.1.2 or earlier

Perform these steps locally while development dependencies are installed:

```bash
composer update redberry/synapse --with-dependencies
php artisan synapse:install
```

The installer does not overwrite customized config or the published gate provider. It moves legacy `bootstrap/providers.php` registration into a conditional registration in `AppServiceProvider`. If it identifies an ambiguous existing registration, remove that registration and related provider references as directed, then rerun the installer.

If your published migrations extend `Redberry\Synapse\Migrations\SynapseMigration`, review/back up any custom edits, then refresh them before removing the package:

```bash
php artisan vendor:publish --tag=synapse-migrations --force
```

For a self-contained published provider, update `app/Providers/SynapseServiceProvider.php` to match the [current stub](https://github.com/RedberryProducts/synapse/blob/v0.1.3/stubs/SynapseServiceProvider.stub): extend Laravel's `Illuminate\Support\ServiceProvider` and guard the `Synapse::auth(...)` call with `class_exists`. Preserve your existing `viewSynapse` gate. The installer deliberately does not overwrite this file. A legacy package-dependent provider is also safe when its unconditional registrations have been removed and only the generated conditional registration remains.

You can then deploy with:

```bash
composer install --no-dev
php artisan migrate --force
```

The standard installation enables the published application provider only in `local`. If you intentionally run Synapse elsewhere, keep the package installed, explicitly register the provider, and configure its gate. Production routes additionally require `SYNAPSE_ENABLED=true`; setting it alone does not grant access.

Compiled assets ship with the package. No npm commands or asset publishing are needed in consuming apps.

## Compatibility and validation

- PHP 8.3+, Laravel 12/13, Laravel AI SDK 0.9/0.10.
- QA on PHP 8.4: 223 unit/feature tests on Laravel 13 / SDK 0.10 and Laravel 12 / SDK 0.9, plus 76 Chromium browser tests.
- Clean Laravel 12/13 installation, repeated installation, cached configuration/routes, and production boot/migrations after `--no-dev` verified.
- Real HTTP streaming with a deterministic four-second tool: first byte in 47–54 ms.

See the [QA report](https://github.com/RedberryProducts/synapse/blob/main/docs/release-qa-2026-09-16.md) for exact versions and scope. Live provider APIs and additional PHP/browser/database/runtime combinations were not exercised in that run.

## Known limitations

Laravel Octane remains unsupported. SDK tool approval/denial events and citations are not fully surfaced in the UI. These are existing limitations, not newly added capabilities in this release.
