# v0.3.0 — Approve tools and inspect every response

Synapse now gives you more control over what your agents do and more visibility into how they answer. This release adds tool approvals, cited sources, completion explanations, and a compact model-step inspector to the Laravel AI playground.

## Approve tools before they run

When the SDK requests approval, Synapse shows the tool's arguments and approval reason before execution. Approve or deny each request, then continue the agent once all decisions are made. Pending approvals survive a page reload, and continuation updates the original answer and tool cards.

Test human approval flows directly in the playground before building them into your application.

This works with custom and SDK tools that support approvals, SDK MCP wrappers, and approval before delegating to a sub-agent. Argument-dependent approval rules are respected. Provider-hosted tool approvals and requests originating inside a child agent are outside this integration.

## See the sources behind an answer

SDK-reported URL citations appear as clickable sources under the assistant's response. Duplicate URLs are combined, missing titles fall back to the hostname, and valid Unicode URLs are preserved. Sources remain available after reload, approval continuation, or a partial failure.

Follow the evidence behind a research answer without digging through raw provider responses. URL handling works on both supported Laravel versions.

Sources appear when the provider supplies citation data; ordinary links in answer text and tool results are not converted into citations. Inline citation highlighting is outside this release. Citations identify the provider's reported sources, not a guarantee of answer accuracy.

## Understand why a response stopped

The playground explains output token limits, content filtering, and explicitly reported cancellation with concise notices. Partial output stays visible, and these completion outcomes do not themselves count as agent failures. Normal completions stay uncluttered; approval pauses and invocation errors keep their existing controls and cards.

The same explanations appear after reload when finish information was recorded.

Use these notices to distinguish a token budget that needs adjusting from an agent invocation that failed.

## Inspect each model round

Expand **Steps (N)** beneath a saved response to inspect its individual model rounds: provider/model, returned text, available reasoning, finish reason, token usage, and associated tool calls/results.

Both the inspector and individual steps start collapsed. Compact headers show the essentials in one line where space permits and wrap to two lines on narrow screens. Opening details never invokes the agent or executes tools.

Newly observed model calls show their own duration, separate from local tool execution and total turn time. Interrupted steps are identified, missing values stay unavailable, and historical completion evidence is marked unverified. Step order and tool associations are retained across failover and approval continuation, without changing the main conversation timeline or aggregate token totals.

Find expensive model rounds, inspect tool handoffs, and diagnose unfinished answers while keeping long conversations compact.

## Upgrade from v0.2.0

**Existing history and attachments are preserved.** Update the Composer constraint explicitly, then publish and run the two additive migrations before opening the updated dashboard:

```bash
composer require --dev 'redberry/synapse:^0.3' --with-all-dependencies
php artisan vendor:publish --tag=synapse-migrations
php artisan migrate
```

The migrations add approval checkpoints and step observations to Synapse's own tables. SDK conversation tables are untouched. Do not clear history for this upgrade. Compiled assets are included; host applications do not need npm or an asset publish step.

Old paused turns lack resumable approval checkpoints and need a new turn. Older history shows sources, completion explanations, and step details only where the necessary data was retained; missing model timings cannot be recovered retroactively.

Requirements are unchanged: PHP 8.3+, Laravel 12.62+ / 13.15+, Laravel AI `^1.3`, and optional Laravel MCP 1.1.0+ when installed. Structured output remains single-shot, and Laravel Octane remains unsupported for streaming.

For verification, rollback considerations, and the separate **0.1.x storage migration**, follow the [upgrade guide](https://github.com/RedberryProducts/synapse/blob/main/UPGRADE.md). The history reset in that legacy procedure does not apply to 0.2.0 installations.

For a new installation:

```bash
composer require --dev 'redberry/synapse:^0.3'
php artisan synapse:install
```
